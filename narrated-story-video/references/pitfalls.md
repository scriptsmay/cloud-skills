# 环境与故障排查

## ffmpeg 滤镜路径（Windows 必读）

`ass=subs.ass` 里的文件名若写成绝对 Windows 路径（`D:\...`）会被滤镜解析器当成 `key:value`，报 `Unable to parse option value` 或找不到字体。

**做法**：合成时把 `cwd` 设为工作目录，字幕固定命名 `subs.ass`，滤镜里只写相对文件名。背景/音频/输出仍用绝对路径。脚本已按此实现，修改脚本时不要改回绝对路径。

zoompan 表达式含逗号，必须用单引号包裹：`z='min(zoom+0.00003,1.08)'`，否则 ffmpeg 把逗号当滤镜分隔符。

## ffprobe 会把 PNG 报成 video

对 `.png` 跑 `ffprobe -show_entries stream=codec_type` 会返回 `video`（单帧图片流）。若据此判断背景类型，图片会被当成视频背景走 `stream_loop`，导致合成失败或画面异常。

**做法**：先按扩展名白名单判定（`.png/.jpg/...` → 图片，`.mp4/.mov/...` → 视频），扩展名未知时才回退 ffprobe。脚本 `is_video()` 已实现。

## 中文字幕豆腐块 / 方块

| 现象 | 原因 | 处理 |
|---|---|---|
| 中文全部变方块 | fontconfig 找不到 `--font` 指定的字体族 | 换 `--font "Microsoft YaHei"` 或 `"SimHei"`，或装 Noto Sans CJK |
| 只有 emoji 是方块 | CJK 字体不含 emoji 字形 | 保持默认（自动换成 ✦）；不要加 `--keep-emoji` |
| 个别符号缺失 | 字体不含该 Unicode 区 | 在原文里替换成常见符号 |

验证字体是否可用：`fc-list :lang=zh family`（Git Bash 可能无此命令，直接看抽帧更快）。

## 背景光晕出现方形色块

手写 PNG 时若光晕循环窗口取 `radius+2`，高斯在窗口边缘仍有较大值，被硬截断成明显矩形。

**做法**：窗口取 `2.6σ + 2`，并在边缘乘 `max(0, 1-(d/r0)^2)^2` 平滑归零。脚本 `add_glow()` 已实现。

## 音频裁剪精度

`-ss` 放在 `-i` 前 + 输出侧重编码（`-c:a pcm_s16le`）= 采样级精确。
不要用 `-c copy` 做 mp3 裁剪：只能在帧边界切（约 26ms 误差），且首帧可能不完整产生爆音——这正是「第 1 秒还有杂音」的常见成因。

片头爆音定位用 `analyze` 子命令的能量表，切点选「突发高电平之后的静音区」，不要一律往后挪 1 秒（会丢有效内容）。

## 尾字被切断（「安」字没读完）

按固定秒数截尾（`--trim-end -1` 之类）最容易出这个错，用户会描述成「最后一个字没读完 / 结尾突然断掉」。

实测：95.167s 的录屏，最后一句「晚安」的高电平在 94.14–94.32s 达峰，94.33–94.42s 快速衰减，94.43s 之后才回到底噪（12–25 dB）。机械地取「结尾前 1 秒」＝94.167s，正好砍在峰值上。另外 95.00s 起还有一段 80 dB 突发音被文件结束硬截断，是录音停止后的杂音/下一段起音，**不能**为了让末字读完整而一路保留到文件末尾。

处理：

1. `analyze --range <dur-3>:<dur> --window 0.02`，用 20ms 窗看最后 3 秒，分清「末字收音 / 衰减 / 底噪 / 尾部突发杂音」。
2. 终点 = 衰减窗结束再往后 0.1–0.3s 余韵，且必须早于尾部突发杂音。上例取 94.60s。
3. 导 mp3 时加 `-af "afade=t=out:st=<裁剪后时长-0.12>:d=0.12"`，只淡出底噪、不碰字音，避免硬切 click。
4. 只补尾部时无需重算字幕时间轴（前段音频完全没变）：把 ASS 末句 End 改成新的「音频时长 + `--tail`」，再用 `--ass` + `--background` 复用原字幕与背景重导，画面可与旧版逐帧一致。

## 结尾停留

音频短于视频时，用 `-af apad=pad_dur=<tail>` 补静音，并用 `-t <duration+tail>` 统一截断；否则部分播放器会在音频结束时截掉画面。
尾句字幕的 End 也要相应延长，否则最后 2 秒是空画面。

## 标题后停顿：只改一边必然不同步

用户说「标题和正文之间停顿久一点」时，最容易只把标题字幕 End 往后拖，或把 ASS 整体后移。两种做法都会让字幕与音频错开 1.2s：

| 改法 | 结果 |
|---|---|
| 只延长标题字幕，音频不变 | 正文已开口，字幕还停在标题，之后整条落后 |
| 所有字幕 +1.2s，音频不变 | 字幕整体落后朗读 |
| 只给音频插静音，字幕不动 | 字幕整体提前 |
| **先给音频插静音，再重新对齐** | 天然同源，见 `alignment.md`；`build --title-pause 1.2` 已内置 |

若成品已交付、只能手改，必须同时更新 ASS / SRT / timeline.json 三处，并先备份 v1（`.ass` / `.srt` / `.mp4`）。用 `--ass` + `--background` 复用背景重导，画面参数不变。

## 批量平移 ASS 把 44 句粘成 1 行

改写 Dialogue 行时若 `",".join(parts)` 后没补回换行，所有字幕会合并成一行，条数从 44 掉到 1，合成后画面只剩第一句。

**做法**：`splitlines(keepends=True)` 逐行处理，`line.rstrip("\n").split(",", 9)`（限制 9 段，防止字幕正文里的逗号被切开），写回时补 `"\n"`。改完立刻校验：

```bash
grep -c "^Dialogue:" story.ass   # 必须等于原句数
wc -l story.ass story.srt
```

实测踩过一次，已从 v1 备份恢复。现在优先用 `build --title-pause` 重跑，避免任何手工平移。

## BMP 内的 emoji 也会变方块

脚本原来只替换 `ord(c) > 0xFFFF` 的字符，但 `☄️` = U+2604 + U+FE0F 全在 BMP 内，会漏过并渲染成方块，只能手工改成 ✦。现已补上「BMP 符号 + 变体选择符 U+FE0F」的替换（`sanitize()`），`晚安 ☄️` 会自动变 `晚安 ✦`。

若遇到不带 VS16 的 BMP 符号（单独一个 `☄`、`♪`）仍是方块，在原文里直接换成 ✦ 或常见字符；`★ ♪ → ✦` 这类正常符号不会被误替换。

## 常见报错

| 报错 | 原因与处理 |
|---|---|
| `Unable to parse option value ... as image size` | zoompan 的 `s=` 或 `scale=` 参数写错；确认 `--width/--height` 是正整数 |
| `Unable to find a suitable output format` / libx264 缺失 | ffmpeg 编译不含 libx264，换 `libx264` 可用版本或改编码器 |
| `silencedetect` 无任何输出 | 音频电平过低或全片无静音；调 `--silence-db` 到 -35 试试 |
| `未检测到朗读停顿` | 音频是配乐/连续语音；本脚本不适用，改用外部时间轴 `--ass` |
| 输出只有几 KB / 0 帧 | 背景图路径错误或 `-t` 过小；检查工作目录 `bg.png` 是否生成 |
| 字幕文字带奇怪的 `｛` `／` | 脚本对 ASS 特殊字符做了转义，属预期行为 |

## 性能参考

- 1080×1920 背景 PNG 生成：约 3–6s（纯 Python 逐像素）
- 86s / 30fps / `veryfast` / CRF 20 合成：约 1 分钟，成品约 3 MB
- 中间 WAV（44.1kHz 单声道 16bit）：约 0.09 MB/秒，裁剪后自动删除未裁剪的临时 WAV
