# 字幕时间轴对齐原理与调参

## 输入假设

自动对齐成立的前提：

1. 音频是**逐句朗读**，句间有 0.3–0.6s 可检测停顿；
2. 语速大致均匀（中文约 4–5 字/秒）；
3. 原文按朗读顺序书写，切句后的句子数与语音段数量接近。

不满足时（配乐、连读无停顿、含大段即兴），不要硬套自动对齐：改由人工给出时间点，或直接用 `--ass` 传外部字幕。

## 前置处理：标题后停顿（默认 1.2s）

睡前故事常把「第 N 天 · 标题」与正文首句连读，两者之间检不出静音，自动对齐会把标题句压到 2.5s 左右，观感太赶。实测听感确认 **1.2s** 合适，此后固定为自动对齐分支的默认值。

**顺序是硬要求：先插静音，再跑下面四步。**

1. `insert_title_pause()` 在切点 `at` 用 ffmpeg `concat` 插入静音，产出 `a2-paused.wav`。
2. 纯语音时间轴 `cum[]` 与总语音时长 `T` **完全不变**（静音被剔除），按字数比例算出的 `v[]` 也不变。
3. 变化只在 `f(u)`：`at` 之后所有有声段起点整体 +1.2s。边界 `v[1]` 吸附到新增的大停顿 `cum[k]` 后，`f(cum[k])` 落在该停顿末尾（正文起音处），于是标题句自然延长、其余句整体后移、尾句 End 与 `--tail` 同步。
4. ASS / SRT / timeline.json 由同一次生成，天然同源，**不需要事后平移**。

实测案例（99.650s 音频 / 44 句，切点 2.845s）：

| | `--title-pause 0` | 默认 1.2s |
|---|---|---|
| 音频时长 | 99.650s | 100.850s |
| 语音段数 | 43 | 44（新增大停顿切开一段） |
| 标题句 | 0–2.473s | 0–4.044s |
| 正文首句起点 | 2.473s | 4.044s |
| 尾句 End | 99.650s | 100.850s |

注意标题句不是简单地 +1.2s（2.473 → 4.044 是 +1.571s）：边界重新吸附到了新停顿的末尾，这比机械平移更贴合正文起音。

**切点算法** `auto_title_pause_at()`：标题与正文连读时，第一个静音段往往在标题内部（实测案例中出现在标题内逗号之后的 1.091–1.512s），不能直接用。算法按标题字数估纯语音时长（默认 3.8 字/秒）沿有声段映射回真实时间，再在 ±0.5s 内用 20ms 能量窗找「最后一个能量低谷 + 其后 ≥15dB 起音跃升」的边界。该案例自动值 2.844s vs 人工 ASR + 能量表确认 2.845s，差 1ms。**自动值仍须复核**（`analyze` 能量表 / ASR 前后短片段），确认后显式传 `--title-pause-at`。

**`--ass` 例外**：外部字幕无法自动后移，脚本在该分支默认关闭停顿并忽略显式 `--title-pause`。若音频换成已插静音的版本，字幕必须来自同一次生成的 ASS，否则整体不同步。

**适用范围**：`is_title_line()` 只在原文首行无句读且长度适中（2~24 权重字）时启用默认停顿。散文 / 旁白首句通常含逗号，脚本跳过并打印提示，避免把静音插进第一句话中间；显式传 `--title-pause` 仍会执行。

## 算法四步

### 1. 停顿检测 → 有声段

```
ffmpeg -i audio -af silencedetect=noise=-42dB:d=0.30 -f null -
```

解析 `silence_start` / `silence_end`，取补集得到有声段 `[(s,e)]`，过滤 <0.25s 碎片。
-42dB 适合「朗读 ≈ -10dBFS、静音 ≈ -80dBFS」这一类干净录音。

### 2. 构造纯语音时间轴

把有声段首尾相接，累计得 `cum[]`，总语音时长 `T`（已剔除所有静音）。
把原文按标点切成 N 句，按字数权重把 `[0,T]` 切成 N 段，得到语音时间轴上的句边界 `v[]`。

权重：CJK 字符 1.0，标点/拉丁/符号 0.25。

### 3. 边界吸附到停顿

对每个内部边界 `v[i]`，在附近 `cum[]` 中挑**大于前一个边界**且距离 ≤ `snap`(默认 0.90s) 的停顿，吸附过去。
「大于前一个边界」这条约束很关键：否则相邻两句会吸到同一个停顿，产生 0 时长字幕。

吸附后强制单调递增（最小间隔 0.20s）。

### 4. 映射回真实时间 + 最短显示

```
f(u) = segs[k].start + (u - cum[k])，k = bisect_right(cum, u) - 1
```

`u` 落在第 k 个有声段内时线性映射；`u` 恰等于 `cum[k]` 时取第 k+1 段起点（即停顿之后）。
因此句边界大多落在朗读停顿处，字幕会自然覆盖相邻静音。

最后做一次「短句借时」：任一 cue < `min_cue`(1.0s) 且相邻 cue > 2×`min_cue` 时，从长句借时间，避免一闪而过。
尾句 End 额外加 `--tail`，让「晚安」等收尾停留到片尾。

## 实测参考

一次 84.67s / 37 语音段 / 38 句的睡前故事（句文为示意文本）：

| 句 | 吸附后区间 | 对应朗读停顿 |
|---|---|---|
| 标题 | 0.00–3.14 | 2.59–3.14 静音后 |
| 在很远很远的地方， | 3.14–6.15 | 5.70–6.15 静音后 |
| 有一颗小小的星星， | 6.15–8.82 | 8.44–8.82 静音后 |
| 它的光很轻很柔， | 8.82–10.11 | 9.73–10.11 静音后 |
| 走过好多好多年， | 10.11–11.44 | 10.98–11.44 静音后 |

前 6 句全部命中正确停顿。局部偏差出现在**连读句**（多个短句共用一个语音段），此时按字数比例切分，误差通常 0.3–0.5s。

## 参数调节

| 现象 | 调整 |
|---|---|
| 标题与正文连读、标题一闪而过 | 默认已插 1.2s 静音；改长短用 `--title-pause`，切点复核后传 `--title-pause-at` |
| 检出的语音段太少，句子挤在一起 | `--silence-db -38`（阈值放宽）或 `--silence-min 0.20` |
| 检出的语音段太多（呼吸声被当停顿） | `--silence-db -46` 或 `--silence-min 0.40` |
| 字幕整体比朗读提前/滞后 | 先查 `--trim-start` 是否切错，再查原文是否漏句/多句 |
| 边界总落在句子中间 | 调大 `--snap 1.2`；仍不行说明停顿与句子数不匹配，需人工整理原文 |
| 短句一闪而过 | 调大 `--min-cue 1.3` |
| 每行字数不合适 | `--line-chars`（1080 宽基准，横屏会按宽度缩放） |

## 切句规则

- 在 `，。？！：；、…` 及 `——` 后切分，分隔符保留在句末
- 后面紧跟右引号/右括号时不切，避免 `"有人在吗？"` 被拆散
- 仅含标点的碎片并入前一句
- 空行分段；Markdown `#` 标题标记自动剥离
- 无句末标点的短行（标题、「晚安」）独立成句，默认用 `--title-first 1 --title-last 1` 的 Title 样式
- 默认把非 BMP 字符（emoji）及「BMP 符号 + U+FE0F 变体选择符」（如 ☄️）替换为 ✦，`--keep-emoji` 可保留

## 产物

- `<输出>.ass`：可编辑字幕（硬字幕烧录用同一份）
- `<输出>.srt`（加 `--srt`）
- `.story-video-work/timeline.json`：每句 index / start / end / text，用于人工校对
- `.story-video-work/frames/check-*.jpg`：首句、中间句、尾句的字幕中点抽帧

## 已知局限

- 无词级时间戳，不能做逐字高亮
- 连读句、语速突变处需人工微调
- 标题后停顿的切点是估算值，必须复核；连读特别紧凑时自动值可能落在标题末字收音里
- 若音频含原文之外的内容（开场白、片尾曲），字数比例会整体偏移；先裁剪干净再对齐
- 需要精确对齐时，可在用户明确同意后把音频送 ASR 取时间戳，再用 `--ass` 导入；本脚本自身不联网
